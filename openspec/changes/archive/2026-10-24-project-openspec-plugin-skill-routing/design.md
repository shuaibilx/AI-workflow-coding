# Design

## Context

The source Plugin at 0.4.0 contains 21 skills, while the active Codex cache is still 0.2.0 and contains only the main workflow and setup skills. This repository also has six OpenSpec skills generated under its own `.agents/skills/` by an earlier `openspec init --tools codex`. Codex loads the installed Plugin package and project-local skills, not the source checkout's `skills/` folder by itself.

## Goals / Non-Goals

**Goals:** Keep OpenSpec's project data under the selected project, route OpenSpec phases to the Plugin-bundled skills, and make the complete Plugin skill set selectable after a Plugin refresh.

**Non-Goals:** Automatically remove project-local skills generated by earlier OpenSpec initialization; change global OpenSpec CLI installation; or add new Plugin/CLI runtime services.

## Decisions

1. Change the CLI's explicit project initialization to `openspec init --tools none`. OpenSpec still creates its project structure in the selected project's working directory, while `none` prevents it from generating a parallel set of project-local agent skills. Preserve any local files already present.
2. Use the stable Plugin namespace `ai-workflow` for explicit skill selection. Document `/skills` as the picker and `$ai-workflow:<skill-name>` as the direct invocation form. The main workflow will name the bundled OpenSpec skill for each phase so those skills work without project-generated copies.
3. Bump the Plugin, package, and workflow metadata together to 0.5.0. Codex's installed cache is versioned; publishing a new Plugin version lets the marketplace install a package containing the current 21 skills. Updating the source checkout alone does not refresh the installed package.
4. Keep the setup CLI's role limited to environment checks and explicit project initialization. Do not make setup delete existing `.agents/skills/openspec-*`; cleanup can remove user edits and is unnecessary for explicit namespaced invocation.

## Risks / Trade-offs

- Existing projects may still expose OpenSpec skills generated by earlier initialization → leave them intact and direct the workflow to the Plugin-namespaced copies; a future cleanup can be done deliberately by the project owner.
- A refreshed source may not immediately change an active Codex session → document marketplace upgrade/reinstall and starting a new chat.
- `--tools none` depends on the supported OpenSpec CLI option → keep the CLI invocation covered by unit and real integration checks.

## Migration Plan

Update initialization behavior, workflow guidance, and bilingual documentation; bump all package version declarations; run unit, package, and integration checks; then distribute the new Plugin version. Users refresh the marketplace installation and open a new chat to load the new skill set.
